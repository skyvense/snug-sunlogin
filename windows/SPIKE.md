# Windows spike：待验证的四个未知数

来源：`~/workspace/snug-windows-feasibility.md`（2026-11-19 可行性研究，未进仓库）。
本分支只杀这四个未知数；全过才谈 MVP 排期。

## 前置条件

- 一台能被向日葵手机端控制的 Windows 10/11 机器（x64）
- 向日葵被控端已装好并能正常被手机控制
- 本应用 `SnugWindows.exe`（GitHub Actions 的 `SnugSunlogin-Windows-Rust` 产物，
  与 `install-vdd.ps1`、`SPIKE.md` 在同一个包里）

## 步骤

1. 双击 `SnugWindows.exe`（会弹 UAC，需要管理员：改 VDD 配置、重启驱动设备要用）。
2. 点「安装 VDD」（或手动跑同目录的 `install-vdd.ps1`），装完看主窗口状态行。
3. 点「创建手机屏」：应用自动把 1080×2346@60 写进 VDD 配置、重启驱动设备、
   并把虚拟屏设成该模式。状态行应显示「手机屏已就绪」。
4. 点「测试窗口」：测试窗口铺满虚拟屏，默认动态模式（帧号持续变、球在弹、竖条在扫）。
5. 用向日葵**手机端**连这台电脑，选这块虚拟屏，看串流是否流畅；
   再点测试窗口左上角「切到静态」，对照静态画面是否流畅。
6. 测完点主窗口「移除手机屏」恢复原配置（原配置备份在
   `C:\VirtualDisplayDriver\vdd_settings.xml.snug-pristine.bak`）。

## 四个未知数（逐项打勾）

- [ ] **U1 手机端能选到并串流这块虚拟屏**：向日葵手机端的屏幕列表里出现虚拟屏，
      能连上、能看到测试窗口。
- [ ] **U2 串流流畅度**：动态模式下帧号跳动是否均匀、有无冻屏；
      与 mac 版卡顿对照（mac 上是纯串流卡，Windows 换了一条抓屏链，结论可能不同）。
- [ ] **U3 动/静对照**：动态卡而静态流畅 → 低变化内容被跳帧/缓冲；
      两种都卡 → 恒定赤字；两种都流畅 → Windows 链没这个问题。
- [ ] **U4 模式稳定性**：创建/移除手机屏各来一遍，虚拟屏模式切换是否可靠、
      物理屏有没有受影响（黑屏、模式被改、HDR 变化之类——mac 上有同类问题，重点看）。

## 回报清单（测完把这些发回主会话）

- 主窗口日志全文（界面日志框，或 `%LOCALAPPDATA%\SnugWindows\snug-windows.log`）
- U1–U4 每项的实际结果；串流卡的话，描述卡法（帧号跳得不匀 / 整屏冻住 / 延迟累积）
- 手机端会话统计（如能看到）：实际帧率、分辨率、延迟、P2P 还是转发
- 任务管理器里 AweSun 相关进程在卡时的 CPU 占用
